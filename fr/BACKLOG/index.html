Backlog Helios Energy¶

Helios Energy installe des panneaux solaires résidentiels en Europe du Sud. Les ventes tournent sur Salesforce, et les équipes de pose suivent chaque installation dans une application sur mesure appelée Helios Delivery.

L'équipe de delivery travaille en itérations de trois semaines. Chaque story ci-dessous est du vrai travail pour l'application Helios Delivery, et chacune est un lab de ce cours.

Les stories en détail¶

US-014 - Montrer à l'équipe de pose combien de panneaux un chantier demande¶

Responsable: Vous
Branch: features/US-014-panels-required
Lab: 1.3

En tant que membre de l'équipe de pose, je veux voir le nombre de panneaux nécessaires sur l'enregistrement d'installation, afin de charger la bonne quantité dans la camionnette.

Critères d'acceptation :

  • Un champ Panels Required existe sur Installation
  • Il est visible par le permission set de l'équipe de pose
  • Les planificateurs peuvent le renseigner
  • Il apparaît sur la page d'enregistrement Installation

US-016 - Permettre à l'équipe de pose de laisser des notes sur une installation¶

Responsable: Vous
Branch: features/US-016-crew-notes
Lab: 1.7

En tant que membre de l'équipe de pose, je veux un champ de notes en texte libre et une vue de liste des installations encore ouvertes, afin de passer le relais proprement à l'équipe suivante.

Critères d'acceptation :

  • Un champ Crew Notes existe sur Installation
  • Une vue de liste Open Installations existe, pour tous les utilisateurs
  • Le permission set de l'équipe de pose donne accès au champ

US-017 - Enregistrer qui a validé une installation¶

Responsable: Romain Panda
Branch: training/mate-us-017-sign-off
Lab: 2.1

En tant que responsable de delivery, je veux le nom de la personne qui a validé l'installation, afin de pouvoir l'appeler quand le client rappelle.

Critères d'acceptation :

  • Le champ est sur la présentation de page
  • Les managers peuvent le lire et l'écrire

US-018 - Plafonner la taille d'équipe qu'un planificateur peut affecter¶

Responsable: Mariia Pyvovarchuk
Branch: training/mate-us-018-crew-capacity
Lab: 2.7

En tant que planificateur, je veux que le flow d'affectation refuse une équipe plus grande que ce que l'installation autorise, afin d'arrêter de surdimensionner les petits chantiers.

Critères d'acceptation :

  • Installation_Assign_Crew vérifie le plafond
  • Les planificateurs peuvent le forcer

US-019 - Générer un PDF de devis depuis une opportunité¶

Responsable: Romain Panda
Branch: training/mate-us-019-quote-pdf
Lab: 2.9

En tant que commercial, je veux un bouton qui génère le PDF du devis, afin d'arrêter de le refaire dans un tableur.

Critères d'acceptation :

  • L'autorisation est donnée aux managers

US-052 - La présentation de page Installation sur deux colonnes¶

Responsable: Mariia Pyvovarchuk
Branch: training/mate-us-052-layout-columns
Lab: 3.2

En tant que planificateur, je veux que la section Information d'une installation utilise ses deux colonnes, afin de voir toute l'installation sans faire défiler.

Critères d'acceptation :

  • Le plafond de capacité d'équipe est dans la deuxième colonne de la section Information
  • Tous les champs qui étaient sur la présentation de page y sont toujours

US-020 - Refactorer InstallationScheduler¶

Responsable: Mariia Pyvovarchuk
Branch: training/mate-us-020-apex-refactor
Lab: 3.4

En tant que développeur, je veux que le scheduler soit découpé en méthodes testables, afin qu'on arrête d'en avoir peur.

Critères d'acceptation :

  • Comportement inchangé
  • Couverture au-dessus du seuil

US-021 - Prévenir le planificateur quand une équipe est trop petite¶

Responsable: Vous
Branch: features/US-021-crew-size-warning
Lab: 2.2

En tant que planificateur, je veux un seul avertissement sur l'installation quand l'équipe affectée est plus petite que ce que les panneaux demandent, afin de corriger avant que la camionnette parte, et pas une nouvelle tâche à chaque enregistrement.

Critères d'acceptation :

  • Le flow Installation Crew Warning existant compare l'équipe et les panneaux
  • L'avertissement est envoyé une seule fois

US-024 - Crew Size devient obligatoire¶

Responsable: Vous
Branch: features/US-024-crew-size-required
Lab: 2.3

En tant que planificateur, je veux que Crew Size soit obligatoire sur toutes les installations, afin qu'aucun chantier ne soit planifié sans équipe.

Critères d'acceptation :

  • Crew Size est obligatoire
  • Les enregistrements existants sont remplis avec la valeur par défaut 2, par un batch qui tient quel que soit le volume

US-026 - Données de référence de capacité d'équipe et recalcul nocturne¶

Responsable: Vous
Branch: features/US-026-crew-capacity-data
Lab: 2.4

En tant que planificateur, je veux des règles de capacité par type d'équipe et un job nocturne qui les recalcule, afin que le tableau de planification soit juste chaque matin et que j'en reçoive un résumé dans ma boîte mail.

Critères d'acceptation :

  • 12 enregistrements Crew Capacity existent dans chaque org
  • Le batch est planifié toutes les nuits
  • Le planificateur reçoit l'e-mail de résumé du matin

US-027 - Vérifier plusieurs installations d'un coup face aux panneaux disponibles¶

Responsable: Vous
Branch: features/US-027-schedule-by-availability
Lab: 2.5

En tant que planificateur, je veux vérifier une liste d'installations face aux panneaux disponibles en une seule fois, afin de remplir une semaine de planning sans ouvrir chaque enregistrement.

Critères d'acceptation :

  • InstallationScheduler renvoie les installations qui peuvent recevoir une équipe un jour donné
  • La couverture reste au-dessus du seuil

US-033 - Les équipes de pose peuvent lire le coût du lot de panneaux¶

Responsable: Vous
Branch: features/US-033-batch-cost-visibility
Lab: 2.6

En tant que membre de l'équipe de pose, je veux voir le coût du lot que je suis en train d'installer, afin de déclarer une casse avec la bonne valeur.

Critères d'acceptation :

  • L'équipe de pose peut lire Panel Batch Cost

US-034 - Les toits plats demandent une équipe d'au moins trois personnes¶

Responsable: Vous
Branch: features/US-034-crew-override
Lab: 2.7

En tant que planificateur, je veux que le flow d'affectation mette au moins trois personnes sur un toit plat, afin que le lestage soit porté sans risque.

Critères d'acceptation :

  • Installation_Assign_Crew augmente l'équipe sur les toits plats
  • Le plafond d'équipe de Mariia, issu de US-018, l'emporte toujours quand les deux se contredisent

US-038 - Ranger la présentation de page Installation¶

Responsable: Vous
Branch: features/US-038-installation-notes-tidy
Lab: 2.8

En tant que planificateur, je veux Crew Size au-dessus d'Install Date sur la présentation de page de l'installation, afin de voir l'équipe avant la date.

Critères d'acceptation :

  • Crew Size est au-dessus d'Install Date sur la présentation de page Installation

US-041 - Checklist de passation d'installation¶

Responsable: Vous
Branch: features/US-041-handover-checklist
Lab: 2.9

En tant que planificateur, je veux une checklist de passation sur l'installation avec ses éléments de référence, afin qu'un chantier ne soit clôturé que lorsque la checklist est complète.

Critères d'acceptation :

  • Un objet Handover_Item__c existe
  • 10 éléments de checklist de référence sont chargés dans chaque org
  • La vérification de clôture existante bloque aussi sur une checklist incomplète

US-045 - Les installations annulées ne peuvent plus être antidatées¶

Responsable: Romain Panda
Branch: fix/US-045-installation-date-hotfix
Lab: 3.7

En tant que planificateur, je veux pouvoir antidater une installation que j'annule au jour où elle a été décommandée, afin de pouvoir clôturer la semaine.

Critères d'acceptation :

  • Les installations annulées échappent à la règle de date, comme les installations terminées
  • La règle refuse toujours de déplacer une installation planifiée dans le passé

US-046 - Statut Needs Reinspection, ajouté en production par un admin¶

Responsable: Vous
Branch: retrofit/US-046-needs-reinspection
Lab: 3.7

En tant que release manager, je veux que le statut ajouté en production par un admin soit dans le repository, afin que la prochaine release ne le retire pas aux planificateurs.

Critères d'acceptation :

  • Needs Reinspection est une valeur de Installation__c.Status__c sur integration
  • Rien d'autre n'est venu de production avec lui

US-055 - Install Date dit de quel jour il s'agit¶

Responsable: Romain Panda
Branch: training/mate-us-055-install-date-help
Lab: 3.11

En tant que chef d'équipe, je veux qu'Install Date dise s'il s'agit du jour où on va sur site ou du jour où les panneaux arrivent, afin que personne ne roule vers un site vide.

Critères d'acceptation :

  • Install Date a un texte d'aide qui nomme le jour dont il s'agit

US-056 - Montrer les panneaux que chaque membre de l'équipe doit poser¶

Responsable: Romain Panda
Branch: training/mate-us-056-crew-workload
Lab: 3.3

En tant que planificateur, je veux voir combien de panneaux chaque personne de l'équipe doit poser, afin d'arrêter de le calculer de tête.

Critères d'acceptation :

  • Une formule Crew Workload sur Installation
  • Sur la présentation de page, lisible par les managers

US-062 - Réunir les delivery managers dans un groupe Crew Leads¶

Responsable: Mariia Pyvovarchuk
Branch: training/mate-us-062-crew-leads
Lab: 3.3

En tant que planificateur, je veux tous les delivery managers dans un même groupe Crew Leads, afin de partager les plannings d'installation une seule fois au lieu de personne par personne.

Critères d'acceptation :

  • Un groupe public Crew Leads qui contient tous les delivery managers
  • La capacité des équipes recalculée une fois après le déploiement

US-057 - Mettre en pause une installation qui attend une pièce¶

Responsable: Mariia Pyvovarchuk
Branch: training/mate-us-057-awaiting-parts
Lab: 3.10

En tant que planificateur, je veux un statut pour une installation bloquée par une pièce manquante, afin que le rapport hebdomadaire cesse de la compter en retard.

Critères d'acceptation :

  • Status propose Awaiting Parts
  • Les planificateurs peuvent le choisir sur une installation déjà planifiée

US-058 - Enregistrer la durée de garantie sur un panel batch¶

Responsable: Romain Panda
Branch: training/mate-us-058-warranty-term
Lab: 3.10

En tant que commercial, je veux que la durée de garantie soit stockée sur le panel batch, afin que le devis dise combien de temps les panneaux sont couverts.

Critères d'acceptation :

  • Un champ Warranty Years existe sur Panel Batch
  • Il est sur la présentation de page Panel Batch
  • Les managers peuvent le lire et l'écrire

US-059 - Enregistrer le fournisseur d'un panel batch¶

Responsable: Romain Panda
Branch: training/mate-us-059-supplier
Lab: 3.10

En tant qu'acheteur, je veux que le fournisseur soit stocké sur le panel batch, afin qu'une demande de garantie parte chez la bonne entreprise sans ressortir la facture.

Critères d'acceptation :

  • Un champ Supplier existe sur Panel Batch
  • Il est sur la présentation de page Panel Batch
  • Les managers peuvent le lire et l'écrire

US-060 - Signaler une installation qui a besoin d'un échafaudage¶

Responsable: Mariia Pyvovarchuk
Branch: training/mate-us-060-scaffolding
Lab: 3.10

En tant que planificateur, je veux signaler une installation qui a besoin d'un échafaudage, afin que l'équipe le réserve avant le jour J au lieu de le découvrir sur place.

Critères d'acceptation :

  • Une case à cocher Scaffolding Required existe sur Installation
  • Elle est sur la présentation de page Installation
  • Les équipes de pose la voient, les planificateurs la cochent

US-061 - Enregistrer le code du portail d'un site¶

Responsable: Mariia Pyvovarchuk
Branch: training/mate-us-061-gate-code
Lab: 3.10

En tant que membre de l'équipe de pose, je veux le code du portail du site sur l'installation, afin d'entrer sans appeler le client à sept heures du matin.

Critères d'acceptation :

  • Un champ Gate Code existe sur Installation
  • Il est sur la présentation de page Installation
  • Les équipes de pose le lisent, les planificateurs le modifient
